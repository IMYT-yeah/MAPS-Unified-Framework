四、⚠️ 一个工具缺陷（已修，且旧的数值全部有效）

(6,6,6) 一度报 list index out of range，一度被误读为"超时"。真因：

GAP 对超长整数会折行 —— (6,6,6) 的 |G| 有 223 位 ⟹ 输出是 ORDER / <数字片段1> / <片段2> / … ⟹ 旧解析器按行取 split()[1] ⟹ IndexError。

修法（_gap.py）：① 加 SetPrintFormattingStatus("*stdout*", false); 尽量不折行； ② 解析器改为「标记行之后、下一个标记之前的所有数字片段拼接成一个整数」。 已自检：(2,2,6) → |G| = 648、(2,4,4) → 220150628352，与已知值一致。

⚠️ 影响面：只有 |G| 超过约 78 位才会触发 ⟹ 本轮与第 48 轮的所有数值都不受影响 （最长的是 (2,6,6) 的 46 位），无需重算。
